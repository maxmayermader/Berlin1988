## Phase Goal

> **Goal (verbatim from ROADMAP.md Phase 3):** A real group can find each other without trading
> codes, the host controls the room, everyone can talk, and one person dropping does not kill the
> match.
>
> **MVP_MODE note:** the ROADMAP `**Goal:**` line is not in user-story format; per the MVP-mode
> contract no story was invented here. See 03-01-PLAN.md's identical note.

**This plan's slice:** one person's laptop dying does not end everyone else's game — a named bot
takes the wheel, and hands it back when they return.

<objective>
Deliver LOBBY-07 and LOBBY-06: every AI-controlled seat named as "{Personality} the {Title}", and a
disconnect → grace period → AI takeover → reclaim lifecycle that keeps a match running without
permanently surrendering a seat.

Two findings from 03-RESEARCH.md shape this plan and correct premises in 03-CONTEXT.md:

1. **`Personality.title` already exists** in `packages/ai/src/personalities/index.ts` (verified: the
   `Personality` interface declares `readonly title: string` and all five personalities populate it,
   e.g. `title: 'The Ghost'` for KATJA). D-09 said this phase "must add a title lookup" — it must
   not. The only work is exposing name and title through the public snapshot.
2. **The `submitOrder()` overwrite race is real, not hypothetical.** `packages/engine/src/submitOrder.ts`
   has no "already committed" rejection code, so a second call for the same agent silently
   overwrites `pendingOrders[agentId]`. A bot submission still queued when a human reclaims their
   seat *will* clobber the human's fresh order if its `releaseAt` lands after. Engine changes are out
   of scope this phase, so the purge belongs in the room layer and must be atomic with the reclaim.

Purpose: LOBBY-06, LOBBY-07 (D-07, D-08, D-09).
Output: `RoomSeat.controlledBy`, `aiReadout` on the public seat schema, `apps/party/src/readout.ts`,
`DisconnectedSeat` + grace scheduling, `takeOverSeat` and `reclaimSeat` in `bots.ts`, and the
three-state seat row.
</objective>
