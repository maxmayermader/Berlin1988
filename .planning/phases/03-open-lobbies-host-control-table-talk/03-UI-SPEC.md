# Phase 03 — UI Design Contract

> Visual and interaction contract for the public lobby browser (HOME-03), host seat-count/kick
> control (LOBBY-01/02), AI takeover readout (LOBBY-06/07), and lobby + match chat (CHAT-01/02/03).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled primitives in `apps/web/components/ui/` |
| Icon library | none — text/glyph labels only (e.g. "AI" badge, ✓/✗), consistent with Phase 1/2 |
| Font | system stack (`ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`) — `apps/web/app/globals.css`, unchanged |

**No shadcn gate run.** `components.json` still does not exist anywhere in the repo. Phase 1 (01-CONTEXT.md
D-10, "clean but plain… no theme… deferred to Phase 4") and Phase 2 both deliberately kept the
hand-rolled Tailwind v4 token system rather than introducing a component library, and this phase's
own briefing repeats that instruction explicitly: match the existing plain/clean Tailwind baseline,
do not introduce new theming. This phase adds exactly one new primitive to `components/ui/`
(a `Banner`/toast-equivalent for the kicked-player notice, see Copywriting Contract and UI
Considerations) — everything else (lobby list rows, seat-count stepper, kick button, chat panel,
flavor-prompt picker) is built from the existing `Button` primitive and existing Tailwind tokens.

## Visual Hierarchy

- **Home page:** `CreateJoinPanel` (Create/Join actions) stays the primary focal point at the top of
  the page — it is the fastest, most-used path and Phase 1 already established it there. The new
  "Open Lobbies" list sits below it as a secondary, scannable list — a discovery aid for players
  without a code, not a competing hero element. The kicked-notice banner, when present, sits above
  both (top of page) so it's the first thing a redirected player sees, but only ever appears once.
- **Lobby page:** unchanged primary focal point (`SeatList` + Ready/Edit Loadout actions). The new
  seat-count control sits directly above `SeatList` as a compact host-only row (not a separate
  panel) — it edits the same list the player is already looking at. Chat is secondary: a distinct
  "Table Talk" section below the existing seat/ready content, not interleaved with it, so a player
  scanning seats never has to visually parse past chat noise.
- **Match page:** unchanged primary focal point (Board ~60% / Orders panel ~40%, per 01-UI-SPEC.md's
  visual-hierarchy flag). Chat is tertiary here — a collapsed-by-default panel docked to a fixed
  corner (bottom-right), expanding on click, so it never competes with the board or the order
  composer for space during active play. An unread-message count on the collapsed toggle is the
  only indicator that new chat has arrived; no motion/animation on the badge itself (POLISH-01's
  transition pass is explicitly Phase 4, not this phase).

## Spacing Scale

Declared values (must be multiples of 4) — identical to the Phase 1/2 scale already in
`01-UI-SPEC.md`/`02-UI-SPEC.md` and used via Tailwind's default numeric utilities (`gap-N`, `px-N`,
`py-N`); no new `--spacing-*` theme keys.

| Token | Value | Usage in this phase |
|-------|-------|-------|
| xs | 4px | Gap between the "X/Y filled" count and host codename in a lobby-list row; gap between a chat message's codename and its timestamp (if shown) |
| sm | 8px | Gap between lobby-list rows; gap between the chat input and its Send button; gap between a flavor-prompt chip and its neighbor |
| md | 16px | Default padding inside a lobby-list row card; default padding inside the chat panel; gap between the seat-count control and `SeatList` |
| lg | 24px | Padding around the "Table Talk" section on the lobby page; padding inside the expanded match chat drawer |
| xl | 32px | Gap between the "Open Lobbies" section and the page's existing content above it |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions:
- **44px minimum click/tap hit-target**, carried over from 01-UI-SPEC.md, applies to the new match
  chat toggle (a small fixed-corner control that must remain easily tappable) and to each seat-count
  stepper option.

## Typography

Reuses the exact 4 sizes / 2 weights already established in Phase 1/2. No new sizes or weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display | 28px | semibold (600) | 1.2 |
| Heading | 20px | semibold (600) | 1.2 |
| Body | 16px | regular (400) | 1.5 |
| Label | 14px | regular (400) | 1.5 |

Usage guide, this phase's additions:
- Heading (20/600/1.2): "Open Lobbies" section title, "Table Talk" section title, chat panel title
- Body (16/400/1.5): chat message text, lobby-list row host codename, seat-count control label
- Label (14/400/1.5): "X/Y filled" count, AI readout text ("{Name} the {Title}"), chat message
  sender codename (rendered semibold — see below) and optional timestamp, flavor-prompt chip text,
  seat-count stepper option labels
- Chat message sender codename uses the Label size at semibold (600) to distinguish it from the
  Body-size message text beneath it, matching how `SeatList.tsx` already bolds a seat's codename —
  no new size introduced, only the existing weight token reused in a new place.

## Color

Reuses the exact `app/globals.css` `@theme` tokens from Phase 1/2. Zero new UI-chrome colors.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (`--color-surface`) | Page background, lobby-list panel background, chat panel background |
| Secondary (30%) | `#f1f5f9` (`--color-surface-secondary`) | Lobby-list row background, chat message bubble background, seat-count control background |
| Accent (10%) | `#2563eb` (`--color-accent`) | See reserved-for list below |
| Destructive (`--color-destructive`) | `#dc2626` | See reserved-for list below |
| Border | `#e2e8f0` (`--color-border`) | All new card/panel/input/chip borders |
| Muted text | `#64748b` | Timestamps, "X/Y filled" secondary text, disabled seat-count options |

**Accent reserved for, and only for:**
- "Join" button on each open-lobby list row
- The currently-selected seat-count option (active/selected state)
- The chat "Send" button fill
- A selected/active flavor-prompt chip's border+text while its picker is open
- Focus rings on any new focusable control (join-list row button, seat-count stepper, chat input,
  flavor-prompt chip), reusing the existing `focus:border-[#2563eb]` pattern

**Destructive reserved for, and only for:**
- The "Kick" button
- The kicked-player banner's left border/icon glyph (background stays neutral secondary, text stays
  `#0f172a` for readability — mirrors 02-UI-SPEC.md's violation-row pattern of destructive-as-accent-
  stripe rather than a full red panel)

Everything else — lobby-list row chrome, chat bubbles, seat-count control chrome, AI-readout text —
uses white/slate neutrals. No new colors, and the AI-readout text explicitly does **not** get its
own accent color (it's informational, not interactive) — plain body-neutral text at the Label size.

## Copywriting Contract

| Element | Copy |
|---------|------|
| "Open Lobbies" section heading | "Open Lobbies" |
| Lobby-list row | "{hostCodename}'s lobby" (Body) + "{seatsFilled}/{seatsTotal} filled" (Label, muted) + "Join" button (accent) |
| Lobby-list empty state | Heading: "No open lobbies" — Body: "No one's hosting right now. Create a game above, or check back in a moment." |
| Kicked banner (home page, D-06) | "You were removed from the lobby by the host." — dismissible via a small "×" button with `aria-label="Dismiss"` (no auto-timeout copy needed; dismiss is manual, matching this project's preference for explicit states over timed disappearance) |
| Seat-count control label | "Seats" (Body, host-only) — options rendered "1", "2", "3", "4"; an option below the current occupied-seat count is visually disabled (greyed, `cursor-not-allowed`) with a `title` attribute: "Can't go below {occupied} — {occupied} seats are filled" |
| Seat-count rejected (server-side race, rare) | "Couldn't change seat count — {reason}. Try again." (inline, same tone as 01-UI-SPEC.md's order-rejection copy) |
| Kick button | "Kick" (destructive-variant `Button`, host-only, never on the host's own row) |
| Kick confirmation | Native `window.confirm()`: "Kick {codename} from the lobby? They can rejoin later using the join code." — mirrors 02-UI-SPEC.md's precedent of using `window.confirm()` for a lightweight destructive guard rather than building a new `ui/Dialog` primitive |
| AI seat readout (LOBBY-07) | "{Personality name} the {Title}" — e.g. "Katja Reiner the Ghost", "Oberst Klaus Vogel the Bureaucrat", "Marek Doležal the Butcher", "Director Halloran the Spider", "\"Sable\" the Mirror" — sourced from `PERSONALITIES[id].name` + `.title` (already in `@berlin/ai`), replaces the current bare "AI" badge entirely on every AI-controlled seat |
| Seat state during disconnect grace period (D-07) | "Reconnecting…" (Label, muted) replaces the seat's ready badge — never shown as "AI" until takeover actually fires, so a player doesn't wrongly think a friend's seat has already been handed to a bot |
| Seat reclaimed notice (D-08, optional toast-equivalent) | No dedicated UI required — the seat's own readout flipping from "{Name} the {Title}" back to the player's codename + ready badge is a sufficient, self-explanatory signal; no extra copy needed |
| Chat panel title (lobby) | "Table Talk" |
| Chat panel title (match) | "Chat" (collapsed toggle label) / "Table Talk" (expanded panel heading) — kept short on the collapsed toggle since match-page real estate is tighter |
| Chat input placeholder | "Say something…" |
| Chat send button | "Send Message" |
| Chat empty state | "No messages yet. Say hello, or pick a line below." |
| Flavor-prompt picker toggle | "Prompts" (ghost-variant button next to the chat input) |
| Flavor prompts (~8-10 lines, Cold War table-talk register, D-12) | "Berlin is nice this time of year." / "Trust no one — especially the quiet ones." / "I have a friend at the Ministry." / "Some doors are better left unopened." / "The wall has ears." / "Nice weather for a defection." / "I know a guy who knows a guy." / "Keep your friends close and your dossiers closer." / "This round smells like a setup." / "See you on the other side." |
| Chat message overflow | Messages are capped at 240 characters at entry (client- and server-validated); rendered messages wrap normally, never truncate |
| Chat send rejected (rare — e.g. wrong phase) | "Message not sent — try again." (inline, brief; no dedicated banner) |

## UI Considerations

Applicable state considerations resolved: 18 covered, 4 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Open Lobbies list | ✅ covered | Renders the defined empty-state heading/body (Copywriting Contract) when the directory has zero registered lobbies |
| loading | Open Lobbies list, before first `DIRECTORY_STATE` frame | 🧪 backstop | Renders a neutral "Connecting…" label (same pattern as 01-UI-SPEC.md's lobby-seat-list loading state) in place of the list; exact layout left to executor discretion, verified visually at UAT |
| error | Open Lobbies list, directory socket disconnects | 🧪 backstop | List simply stops updating (stale-but-visible) rather than clearing to empty or showing a hard error — a directory-party outage should never make the home page look broken when direct code-join (HOME-02) still works; held-out visual check at UAT, no dedicated error copy |
| populated | Open Lobbies list | ✅ covered | One row per registered lobby, each showing host codename + "X/Y filled" + Join button (Copywriting Contract) |
| zero-one-many | Open Lobbies list row count | ✅ covered | 0 rows → empty state; 1-N rows → identical row component repeated, no special-casing a single lobby |
| overflow | Open Lobbies list, many simultaneous open lobbies | ✅ covered | List scrolls vertically inside its own section once it exceeds a reasonable viewport height (no hard cap on registered lobbies this phase, per RESEARCH.md's accepted "stale phantom entry" gap) |
| long-text | Host codename in a lobby-list row | ✅ covered | Reuses the existing 20-character codename cap + CSS-ellipsis truncation rule from 01-UI-SPEC.md — same data field, same handling |
| empty | Chat panel (lobby and match, before any messages) | ✅ covered | Renders the defined empty-state copy (Copywriting Contract) instead of a blank scroll area |
| populated | Chat panel | ✅ covered | Messages render newest-at-bottom, each showing sender codename (Label, semibold) above message text (Body); free-text and flavor-prompt messages render identically — no visual distinction between the two message kinds, since D-12 treats them as one log |
| overflow | Chat panel, many messages | ✅ covered | Message list scrolls internally within a fixed-height panel (lobby: fixed section height; match: fixed drawer height); the panel itself never grows the page layout |
| long-text | Chat message text | ✅ covered | Wraps normally inside its bubble, capped at 240 characters at entry (Copywriting Contract) so no single message can dominate the scroll area |
| zero-one-many | Chat message count (0 to many per session) | ✅ covered | 0 → empty state; 1-N → identical row component; no pagination or truncation of history this phase (per D-10, each log lives only as long as its phase) |
| error | Chat send rejected | ✅ covered | Renders the defined inline error copy (Copywriting Contract); input retains the unsent draft text so nothing is lost |
| loading | Chat send, awaiting broadcast echo | 🧪 backstop | Send button reuses the existing `Button` `pending` prop (disabled + reduced opacity, no spinner per D-10) for the brief round-trip; held-out visual check, not a hard requirement |
| populated | Seat-count control | ✅ covered | Always renders 4 fixed options (1/2/3/4); the currently-selected count shows the accent selected state; options below the occupied-seat count render disabled per D-05 (Copywriting Contract) |
| error | Seat-count change rejected (rare server-side race) | ✅ covered | Renders the defined inline error copy (Copywriting Contract), control reverts to the last-confirmed count |
| partial | Seat rows during a live AI takeover / reclaim transition (D-07/D-08) | ✅ covered | Three distinct, mutually exclusive seat states now exist and are each explicitly styled: normal (codename + ready badge), "Reconnecting…" (grace period, muted Label text, Copywriting Contract), and AI-controlled ("{Name} the {Title}", Copywriting Contract) — a seat is never shown in two of these states at once, and the transition between them requires no new copy beyond what's already defined |
| zero-one-many | Kick button visibility across 1-4 occupied seats | ✅ covered | Rendered on every occupied, non-self, non-open seat row when the viewer is host; rendered on zero rows for a non-host viewer or in a 1-seat solo lobby (no one else to kick) |
| loading | Kick button, awaiting KICK round-trip | 🧪 backstop | Reuses the existing `Button` `pending` prop (disabled + reduced opacity, no spinner per D-10), same pattern as the chat-send button's loading row above; held-out visual check, not a hard requirement |
| error | Kick rejected (rare race — target seat already vacated) | ✅ covered | Transient inline message: "Couldn't remove that player — they may have already left." (extends the Copywriting Contract's error-copy pattern); host's seat list re-syncs from the next `ROOM_STATE` frame regardless |
| overflow / long-text | AI seat readout ("{Personality} the {Title}") | ✅ covered | Reuses the same 20-character-cap + CSS-ellipsis truncation rule as the host-codename row above — the longest readout ("Director Halloran the Spider") fits the existing seat-row width without truncation in practice, but the same fallback applies if a future personality's name+title is longer |
| loading / error | Kicked banner (home page) | ✅ covered | Not applicable — the banner renders synchronously from a `KICKED` message already received over the open connection, and its only interaction (dismiss) is a local UI-only action that cannot fail or need a load state |
