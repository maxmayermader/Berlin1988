<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub repository → Vercel build container | A commit reaching the connected branch causes code to execute in a container holding the project's environment variables |
| Vercel project settings → build output | Build Command and environment variables determine what ships; they live outside the repository and outside code review |
| public internet → deployed site | Anyone with the link, by design (D-06) — including every preview URL (D-01) |
| maintainer account → Vercel + GitHub App | The authorization granted in Task 1 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-07 | Tampering | build configuration (Build Command, env vars) | high | mitigate | No `vercel.json` is created (05-RESEARCH.md assumption A2, reaffirmed as a security property here): the Build Command and all environment variables live only in dashboard project settings, so no branch, fork, or pull request can alter what the build runs or inject a variable. Task 1 step 10 and Task 1's acceptance criteria both assert the file's absence. |
| T-05-08 | Elevation of Privilege | Vercel GitHub App repository scope | medium | mitigate | Task 1 step 2 requires installing the App with access to the single `Berlin1988` repository rather than "All repositories", bounding the blast radius of a Vercel-side compromise to this one repo. |
| T-05-09 | Information Disclosure | public preview deployments and the shared open-lobby list | low | accept | D-01 is an explicit user decision made with this consequence stated: every branch gets a public preview URL pointed at the production PartyKit host, so preview lobbies appear in the list real players browse.
