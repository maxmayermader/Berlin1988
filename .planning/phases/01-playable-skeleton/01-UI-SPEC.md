# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — `apps/web` is a fresh skeleton (no `components.json`, no `tailwind.config.*` present yet); shadcn was evaluated and **deliberately not initialized this phase** |
| Preset | not applicable |
| Component library | none — hand-authored Tailwind utility components (button, card, badge, panel) kept deliberately plain per D-10 |
| Icon library | none — inline SVG for board edge/node glyphs and a small hand-drawn set (checkmark, clock, chevron, lock) inlined as SVG; no npm icon package added this phase |
| Font | System font stack via Tailwind v4's default `font-sans` (`ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`) — no custom font import |

**Why no shadcn this phase:** CONTEXT.md's D-10 explicitly locks "clean but plain — basic Tailwind layout, readable typography/spacing, buttons that look like buttons. No theme... no custom illustration," and RESEARCH.md's Standard Stack (Next.js, React, PartyKit, `partysocket`, Zustand, Tailwind v4, Zod, Motion, `nanoid`) does not list shadcn or Radix as a dependency to install. The match board is a bespoke inline-SVG node graph, not a form-heavy CRUD surface — the screens this phase needs (home, lobby, board, step-through, result) are small in number and shadcn's value (a themed component system) is exactly what D-10 asked to defer. Revisit in Phase 2 (deckbuilder — card grid, filters, a real form-heavy surface) where a component library pays for itself faster. If a future session wants shadcn for Phase 1 after all, run the shadcn Initialization Gate before writing any component code — do not retrofit mid-phase.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inline padding |
| sm | 8px | Compact element spacing (seat row internals, submitted-count badges) |
| md | 16px | Default element spacing (form fields, card padding) |
| lg | 24px | Section padding (lobby seat list panel, board side panel) |
| xl | 32px | Layout gaps (home page action columns, match board vs. order panel) |
| 2xl | 48px | Major section breaks (page header to content) |
| 3xl | 64px | Page-level spacing (top/bottom page margins) |

Exceptions:
- **44px minimum click/tap hit-target** on every SVG board node — the *visual* node circle can render smaller (`duel12`'s 12 nodes at typical viewport render well under 44px), but the actual clickable/tappable area (invisible padding, not a rendered spacing value) must be at least 44px in diameter, matching common touch-target accessibility guidance even though this app is desktop-first (per PROJECT.md, "mobile just needs to not be broken" — this is the one place that matters most: misclicking a node during order composition is a real usability failure).

## Typography

3 sizes would undershoot this phase's range (home hero vs. result-screen winner announcement vs. dense board labels); declaring 4.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display | 28px | semibold (600) | 1.2 |
| Heading | 20px | semibold (600) | 1.2 |
| Body | 16px | regular (400) | 1.5 |
| Label | 14px | regular (400) | 1.5 |

Two weights only, used everywhere: **regular (400)** for body/label/reading text, **semibold (600)** for headings, display text, and button labels. No italic, no light/bold extremes.

Usage guide:
- Display (28/600/1.2): home page title, result-screen winner announcement
- Heading (20/600/1.2): lobby "Seats" panel title, match board panel titles, "Resolution" step-through title
- Body (16/400/1.5): paragraph copy, form inputs, button labels, seat rows
- Label (14/400/1.5): countdown timer, "N of M submitted" counter, node names on the board, codename captions under agent markers, badges

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (white) | Page background, board canvas background |
| Secondary (30%) | `#F1F5F9` (slate-100), borders `#E2E8F0` (slate-200) | Cards, lobby seat-list panel, match board side panel, badges, edge lines on the map |
| Accent (10%) | `#2563EB` (blue-600) | See reserved-for list below — primary interactive elements only |
| Destructive | `#DC2626` (red-600) | Destructive/lethal-action elements only |

**Accent (`#2563EB`) reserved for, and only for:**
- Primary CTA buttons: Create Game, Join Game, Ready Up, Start Match (solo AI-fill), Submit Orders, Next (resolution step-through)
- The currently-selected agent/node during order composition (selection ring + legal-move highlight)
- Countdown timer numerals when under 10 seconds remaining (urgency state — a style change, not an animation, so it does not conflict with D-10's "no animations beyond D-06")
- Active/focused form input border (join-code field, codename field)

**Destructive (`#DC2626`) reserved for, and only for:**
- "Retract order" button (undo a submitted-but-not-yet-resolved order, before the round deadline)
- The STRIKE action's target-node highlight while actively being composed (visual cue that this action is lethal — cleared once composition ends)
- `ELIMINATION` outcome styling on the result screen (when that specific `OutcomeReason` applies)

Everything else — node fills, edge lines, seat rows, badges, panel chrome, disabled states — uses white/slate neutrals. No other color is introduced this phase (no sector-brand colors beyond what the engine's own `Sector` data implies for extraction-node labeling, kept as a small neutral-toned text label, not a colored fill, to avoid a second accent competing with blue).

## UI Considerations

Applicable state considerations resolved: 10 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Lobby seat list (open seats before AI/human fills them) | ✅ covered | Empty seats render the "Open Seat" / "An AI opponent will join when the match starts." copy defined in Copywriting Contract until filled. |
| loading | Home page, Create/Join button while awaiting room-server ack | 🧪 backstop | Button enters a disabled "pending" visual state (reduced opacity, no spinner animation per D-10) until the server responds; no copy locked beyond the button's existing label — held-out visual-state test at verification, not a hard requirement. |
| loading | Lobby, WebSocket connecting before first `RoomState` snapshot arrives | 🧪 backstop | Panel renders a neutral "Connecting…" label (Label-role text) in place of the seat list until the first snapshot; exact layout left to executor discretion, verified visually at UAT. |
| error | Home, invalid/unknown join code | ✅ covered | Renders the exact copy in Copywriting Contract's "Invalid/unknown join code" row, inline under the input, in the destructive-adjacent neutral tone (not full red — this is a correction, not a lethal action) using standard body text weight. |
| error | Match, order submission rejected by server | ✅ covered | Per RESEARCH.md Pitfall 2/2b: "locked-in" UI state is driven only by an explicit server ack, never an optimistic local flag. On rejection, the composer returns to editable state and shows the exact copy in Copywriting Contract's "Order submission rejected" row. |
| error | Match, connection lost mid-match (D-11 accepted gap) | ✅ covered | Renders the exact copy in Copywriting Contract's "Connection lost mid-match" row — an explicit terminal state, not a silent hang, even though no reconnection logic exists this phase. |
| partial | Lobby, mixed ready/not-ready seats | ✅ covered | Each seat independently renders its own ready badge (Ready ✓ in accent tone vs. neutral "Not ready"); countdown only appears once the ≥50%-of-filled-seats threshold (LOBBY-04) is met, recomputed after every seat/ready change per RESEARCH.md Pitfall 5. |
| zero-one-many | Match, "N of M submitted" count | ✅ covered | Counter uses the same server-authoritative count regardless of how many of the M are bot seats vs. human seats (bots route through the identical `submitOrder()` path per RESEARCH.md Pitfall 6) — 1-of-1 through 4-of-4 all render with the same component, no special-casing solo/AI-filled matches. |
| zero-one-many | Resolution step-through, event count per round | ✅ covered | The client renders exactly one row per entry in the already-fog-filtered `ResolutionEvent[]` array (per RESEARCH.md Pattern 3); a priority step that produced zero events for a given round simply has no corresponding array entry — nothing is rendered for it, no empty/placeholder row needed. |
| overflow | Player-entered codename (D-09, rename before match) | ✅ covered | Codenames are capped at 20 characters at entry (validated both client-side for UX and server-side as the authoritative limit); anywhere a codename renders as a label (seat row, board agent marker, locked-in badge, result screen) it truncates with CSS ellipsis rather than wrapping or breaking layout. |
| overflow | Match board, up to 4 simultaneous "locked-in" badges | ✅ covered | The locked-in row reserves a fixed 4-slot layout (matching `MatchSettings.seats` max) regardless of actual seat count, so 1-4 badges never cause a reflow as players submit in arbitrary order. |
| long-text | Result screen, `ROUND_LIMIT` outcome copy referencing a codename | ✅ covered | Uses the same 20-character truncation rule as the codename overflow row above — no separate handling needed since it's the identical data field. |
