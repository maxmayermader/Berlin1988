## Phase Goal

**As a** group of players, **I want to** go from the home page through a lobby into a complete 14-round match and see a result, **so that** we can actually play Berlin 1988 in a browser.

This plan delivers the first vertical slice of that story: *create a game and join it by code*.

<objective>
Stand up `apps/web` and `apps/party` from empty skeletons and prove one real end-to-end round-trip: home page → PartyKit Durable Object → authoritative `RoomState` write → per-connection projection → rendered lobby, with a second browser joining the same room by code.

Purpose: this is the Walking Skeleton. It fixes the transport, the wire-protocol home, the fog chokepoint, and the local dev loop that all five later plans in this phase build on without modification. Getting it wrong is the only architectural dead-end left in Phase 1 — the engine, AI and shared types are already complete and tested (69 green).

Output: two runnable apps, `packages/shared/src/protocol.ts`, a room-level integration test harness, a two-browser Playwright E2E, and `pnpm dev` running the full stack locally.
</objective>

<testing_note>
This plan — and every later plan in Phase 1 — puts client logic in pure modules under `apps/web/lib/` and unit-tests them as `.ts` files with Vitest, then proves the rendered result with Playwright. There are **no React component tests and no `.tsx` test files anywhere in this phase.**

That split is deliberate on three grounds. A React DOM testing stack is **not** in `01-RESEARCH.md`'s Package Legitimacy Audit, so introducing one would require the full legitimacy protocol and a blocking human checkpoint before install. `01-RESEARCH.md`'s Validation Architecture table names "React Testing Library **or** Playwright" for exactly this row, and `docs/ARCHITECTURE.md` §6 already commits the project to Playwright for browser-level proof. And keeping logic out of the components satisfies `apps/web/app/CLAUDE.md`'s "keep route files thin — logic belongs in `components/` and `lib/`."

The practical rule for the executor: if a behaviour can be asserted on a value, it belongs in a `lib/*.test.ts`; if it can only be asserted on a pixel or a click, it belongs in `e2e/*.spec.ts`. Plans 01-03 through 01-06 follow the same convention (`board.test.ts`, `orderDraft.test.ts`, `clock.test.ts`, `stepThrough.test.ts`, `format.test.ts`).

**`packages/shared/src/protocol.ts` — the wire contract, Zod-first.** Declare `z.object` schemas and derive TS types with `z.infer`; never hand-write a parallel interface. This task defines only the join slice; Plans 01-02 and 01-03 extend the same unions.
Client to server: `{ type: 'CREATE', codename: string }`, `{ type: 'JOIN', code: string, codename: string, token?: string }`. Codename constrained by `z.string().trim().min(1).max(20)` — this is the authoritative cap; the client cap is UX only.
Server to client: `{ type: 'ROOM_STATE', snapshot: LobbySnapshot }`, `{ type: 'ERROR', code: 'UNKNOWN_CODE' | 'ROOM_FULL' | 'BAD_MESSAGE' | 'WRONG_PHASE', message: string }`, and `{ type: 'JOINED', playerId: string, token: string, code: string }`.
`LobbySeat` = `{ index: number, playerId: string | null, codename: string | null, faction: Sector, kind: 'HUMAN' | 'BOT' | 'OPEN', ready: boolean }`. `LobbySnapshot` = `{ code, phase: 'LOBBY' | 'LOADOUT' | 'IN_GAME' | 'ENDED', hostPlayerId, seats: LobbySeat[] }`. `LobbySnapshot` carries lobby bookkeeping only — it has no field that could hold agent positions, safehouse, traps or cooldowns, and nothing derived from `GameState` may be added to it.
Export `clientMessageSchema` and `serverMessageSchema` as `z.discriminatedUnion('type', [...])`, plus the inferred `ClientMessage`/`ServerMessage` types. Re-export the module from `packages/shared/src/index.ts`.

**`apps/party/src/state.ts` — `RoomState` and pure transitions.** `RoomState` = `{ code, matchId, phase: 'LOBBY' | 'LOADOUT' | 'IN_GAME' | 'ENDED', hostPlayerId, seats: RoomSeat[], gameState: GameState | null }` with `gameState` staying `null` for the whole of this plan. `RoomSeat` extends the wire `LobbySeat` with the server-only `token`. Keep the four-phase shape per SKELETON.md so Phase 2 fills `LOADOUT` without a state-machine change; note in a header comment that `RoomState.phase` is not the engine's `MatchPhase`. Export a pure `toSnapshot(state: RoomState): LobbySnapshot` that strips `token`.
Assign seat factions from `SECTORS` in index order; seat count is fixed at 4 for this phase (host seat-count control is Phase 3).

**`apps/party/src/auth.ts` — connection to seat binding.** `bindConnection(state, connectionId, playerId, token)`, `seatFor(state, connectionId): RoomSeat | null`, and `mintToken(rng)` producing an opaque room-minted token. Every handler resolves the acting player through `seatFor`; a `playerId` arriving in a message body is ignored. Tokens come from the room, never the client.

**`apps/party/src/room.ts` — the PartyKit `Server`.** In `onMessage`, `clientMessageSchema.safeParse(JSON.parse(raw))` first; on failure reply `ERROR { code: 'BAD_MESSAGE' }` and return — a malformed frame must never escape `onMessage` as a throw. Dispatch the parsed message to `handlers.ts`. Attach all per-connection logic in `onMessage`/`onClose` only, never in `onConnect`, and persist `RoomState` to `this.room.storage` after every mutation, rehydrating in `onStart` — Durable Objects hibernate between messages and the 90-second order window is exactly when that happens (RESEARCH.md Pitfall 3). Use only the engine's seeded PRNG (`seedRng` from `@berlin/engine`) for any randomness; the global JS random function is banned repo-wide below `apps/` and stays banned here so a match replays identically from its seed.

**`apps/party/src/handlers.ts` — one function per inbound type.** `CREATE` mints the join code (import from `joinCode.ts`, which Task 2 builds — until then call a locally declared `newJoinCode()` stub with the same signature and replace the import in Task 2), writes `RoomState`, binds the caller to seat 0 as host, replies `JOINED` then `ROOM_STATE`. `JOIN` matches the room's own code, rejects with `ERROR { code: 'UNKNOWN_CODE' }` on mismatch and `ROOM_FULL` when no open seat remains, otherwise binds the next open seat and replies `JOINED`. Handlers return a result; they never call `connection.send` themselves.

**`apps/party/src/broadcast.ts` — the sole outbound path.** Export `sendTo(connection, msg: ServerMessage)` and `sendLobby(room, state)` which iterates `room.getConnections()` and sends each connection the snapshot. Every function here validates its payload against `serverMessageSchema` before serialising. Room-wide fan-out is permitted here only for `LobbySnapshot`, which is public-by-construction; anything derived from `GameState` must go through a per-connection `projectView` call, which Plan 01-03 adds to this same module. State a header comment that this file is the fog chokepoint.
