## Phase Goal

**As a** group of players, **I want to** go from the home page through a lobby into a complete 14-round match and see a result, **so that** we can actually play Berlin 1988 in a browser.

This plan delivers the fourth vertical slice: *see the city, and give your agent its two orders*.

<objective>
Build the match screen: the `/match/[code]` route, the inline-SVG node graph of divided Berlin rendered entirely from `PlayerView.map`, and the two-slot-per-agent order composer whose affordances come from `legalOrders()` rather than from a second, drifting idea of what is legal.

Purpose: this is the surface the whole game happens on, and the two places it can go structurally wrong are both cheap to prevent now and expensive to fix later. Rendering an opponent marker with `display: none` would undo every fog control in the room server; hand-rolling a "what can this agent do" list would silently offer moves the engine will reject, or hide moves it would allow. Both are called out by name in `apps/web/components/board/CLAUDE.md` and `01-RESEARCH.md`'s Don't Hand-Roll table.

Output: a player who has readied up lands on a board, clicks two things, presses Submit Orders, and gets a server ack — with the board's maths and the composer's rules living in pure modules that a unit test can exercise in milliseconds.
</objective>

**`apps/web/lib/board.ts` — the pure maths, no React.**
`projectNode(node: MapNode): { cx: number; cy: number }` maps the 0-100 percentages onto a fixed `0 0 100 100` viewBox, so the SVG is responsive without recomputation.
`edgePath(from: MapNode, to: MapNode): string` returns the `d` attribute for a straight segment between two nodes.
`HIT_TARGET_PX = 44` is the invisible click/tap radius from `01-UI-SPEC.md`'s spacing exception — the rendered circle is smaller, the hit area is not, because misclicking a node while composing an order is a real usability failure.
`adjacentTo(map, nodeId): NodeId[]` and `traversalOrder(map, fromId, direction): NodeId | null` give the keyboard navigation its answer without any component doing geometry. Both read `MapNode.edges`; neither branches on the map id.

**`apps/web/components/board/Board.tsx`** takes `{ map, agents, visibleNodes, activeBlockades, selectedNodeId, legalTargets, onSelectNode }` and renders an SVG with `viewBox="0 0 100 100"` and `preserveAspectRatio`. It maps over `map.nodes` for `MapNode` and over each node's `edges` for `MapEdge`, de-duplicating the bidirectional pairs. There is no branch on `map.id` and no literal node id anywhere in this folder: a map with a different node count must render correctly with zero changes here, which is `apps/web/components/board/CLAUDE.md` rule 1 stated as a testable property.

**`MapNode.tsx`** renders the visual circle, an invisible `HIT_TARGET_PX` hit circle, the node name in the Label role, and markers driven by data: dossier count from `visibleNodes[id].dossiers`, an informant glyph from `hasInformant`, a U-Bahn glyph from `isUBahnStation`, an extraction glyph from `extractionFor`, and a blockade overlay from `activeBlockades[id]`. Sector is encoded by **shape and a text label**, never by fill colour alone (`apps/web/components/CLAUDE.md`). The selection ring and the legal-target highlight use the accent `#2563EB` and nothing else does.

**`MapEdge.tsx`** styles by `Edge.type` only: `STREET` solid, `TUNNEL` dashed, `CHECKPOINT` double line, per `docs/GAME_DESIGN.md` §3.1.

**`AgentToken.tsx`** takes the agent **list** from `view.self.agents` and renders one token per living agent at its node. It has no prop, and can have no prop, for another player's agent — `OpponentPublicInfo` has no field that could supply one. Do not add a "revealed rival" prop in this phase: nothing in `PlayerView` can fill it, and an unfillable prop is an invitation.

**`apps/web/lib/uiStore.ts`** is the second Zustand store, holding selection and pending state only: `selectedAgentId`, `draftByAgent: Record<string, OrderDraft>`, `hoverNodeId`, `connectionStatus: 'connecting' | 'open' | 'lost'`.
