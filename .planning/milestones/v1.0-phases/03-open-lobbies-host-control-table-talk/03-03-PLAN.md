## Phase Goal

> **Goal (verbatim from ROADMAP.md Phase 3):** A real group can find each other without trading
> codes, the host controls the room, everyone can talk, and one person dropping does not kill the
> match.
>
> **MVP_MODE note:** the ROADMAP `**Goal:**` line is not in user-story format; per the MVP-mode
> contract no story was invented here. See 03-01-PLAN.md's identical note.

**This plan's slice:** everyone in the room can talk to each other — in the lobby and mid-match —
in free text and in the game's own Cold War register.

<objective>
Deliver CHAT-01, CHAT-02 and CHAT-03: a `CHAT_SEND`/`CHAT_MESSAGE` wire pair with server-resolved
codename attribution, two phase-scoped logs (D-10), a lobby "Table Talk" panel, a collapsed
bottom-right match drawer, and a curated flavor-prompt picker (D-12) in both.

The whole design pressure here is that chat is the first surface in this codebase that carries
free-form human text across the fog boundary. Every existing message either carries a bounded enum,
a node id the engine re-validates, or nothing at all. So: the sender is never read from the message
body, the delivery is a single identical payload to every connection, and the payload's field set
is fixed by a strict Zod schema.

Purpose: CHAT-01, CHAT-02, CHAT-03 (D-10, D-11, D-12).
Output: `CHAT_SEND`/`CHAT_MESSAGE` schemas and `FLAVOR_PROMPTS` in `packages/shared`,
`apps/party/src/chat.ts`, `handleChatSend`, `sendChat`, `apps/web/lib/chatStore.ts`,
`apps/web/lib/chatRows.ts`, `ChatPanel.tsx` and `MatchChat.tsx`.
</objective>
