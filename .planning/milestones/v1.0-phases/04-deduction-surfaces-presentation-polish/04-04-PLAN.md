<objective>
POLISH-01: the app stops looking like a prototype, consistently, on every screen — and the whole motion
system answers to one reduced-motion decision made in one file.

Plan 04-01 created `apps/web/lib/motion.ts` and used it for the new Intel surfaces. This plan finishes
the job everywhere else: the four route roots get a mount entry, the two `Button` variants get hover
fills, the deckbuilder tiles flip, `MatchChat` finally animates (its own source comment has deferred
this to Phase 4 since Phase 3), and `StepThrough.tsx` — the file the shared utility was extracted
*from* — moves onto it, so the app is left with exactly one reduced-motion code path rather than two.

Purpose: consistency is the deliverable. A durations-and-easings token set that half the app ignores is
worse than none, because the next component author copies whichever call site they happen to open.
Refactoring the original inline pattern is what makes the shared utility the obvious path rather than
an optional one.

Output: `PageTransition.tsx`, hover-enabled `Button.tsx`, four animated route roots, three refactored
or newly-animated components, `apps/web/lib/motionPass.test.ts`, and a human sweep of the whole app
with the OS reduced-motion preference on.
</objective>
