<objective>
The tracer for MATCH-06: a round history that is filtered **once, at the moment each round resolves**,
persisted on the server, delivered inside `PlayerView`, and visible on screen in a corner-docked Intel
drawer during a live match.

This is one vertical slice through every layer the phase touches — `packages/shared` types →
`createMatch` initialization → the `resolveRound` pipeline → the `projectView` fog boundary → the
`apps/party` pass-through (zero edits needed) → the browser panel → the match route mount. It is
production code, not a prototype: the only functionality gaps left for later plans are the row
headline text, expand-to-replay, and the Burn Track tab.

Purpose: prove the history architecture end-to-end before any of it is built out horizontally. The
dangerous half of this phase is the fog-of-war correctness of historical filtering (RESEARCH.md
Pitfall 1/2); proving it on the first commit is far cheaper than discovering it after four layers are
already committed.

Output: `GameState.history`, `PlayerView.history`, `apps/web/lib/motion.ts`, `RoundHistoryPanel.tsx`,
`MatchIntelDrawer.tsx`, `packages/engine/tests/history.test.ts`, and the extended fog-leak scan.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `GameState` → `PlayerView` (`projectView`) | The one sanctioned path for match state to leave the engine toward a client. This plan adds a field that crosses it. |
| `resolveRound()` draft → stored history | The moment of reduction. Anything stored wrong here is wrong forever, and is re-served on every subsequent view. |
| PartyKit room → browser (`ROUND_RESOLVED` / `VIEW` frames) | Serialized `PlayerView`; type-safety here is not wire-safety, which is why the scan in `packages/engine/tests/fog-leak.test.ts` operates on `JSON.stringify` output. |
