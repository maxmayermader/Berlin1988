# Phase 04 — UI Design Contract

> Visual and interaction contract for the round history panel (MATCH-06), the Burn Track panel
> (MATCH-07), and the app-wide motion pass (POLISH-01). Generated by gsd-ui-researcher, verified
> by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled primitives in `apps/web/components/ui/` (`Button`, `Banner`), extended this phase with a shared motion utility, not a component library |

## Visual Hierarchy

- **Match page:** Board (~60%) / Order composer (~40%) stays the unchanged primary focal point (01-UI-SPEC.md, reaffirmed 03-UI-SPEC.md). `MatchChat` keeps its existing bottom-right corner dock, collapsed by default. The new **Intel drawer** (Round History + Burn Track) docks bottom-**left**, also collapsed by default, so a player scanning the board never has two competing docked panels fighting for the same corner. Only one of the two drawers (Chat, Intel) is expanded at a time is *not* enforced — both may be open simultaneously; each is independently sized (`h-96 w-80`, matching `MatchChat`'s existing dimensions) so two open panels never overlap the board's 60% column at desktop widths (≥768px, the existing `md:` breakpoint already used by the board/composer split).
- **Result screen:** unchanged primary content (winner headline, explanation, scoreboard). The Intel drawer's toggle persists on the result screen too — MATCH-06's "past resolutions in the current match" reasonably includes the match that just ended, and `PlayerView.history` (the new field, see Copywriting/Considerations) is still populated at that point. No new primary content competes with the result headline.
- **Home / Deckbuilder / Lobby:** no new panels or layout changes this phase — POLISH-01 here is purely a motion/interaction-feedback pass over the *existing* layout (hover states on existing buttons and rows, loading feedback on existing pending actions, page-entry transitions on route mount). Visual hierarchy established in 01-UI-SPEC.md/02-UI-SPEC.md/03-UI-SPEC.md is unchanged.
- **Card flips**, specifically: (1) `CardGrid.tsx` tiles — selecting/deselecting a card in the deckbuilder gets a brief flip-scale affordance (replacing today's instant background-color swap) so a click reads as "the card turned to face you," matching the game's own card-based fiction; (2) new Burn Track entries — the call-out animation (D-06) is a card-flip reveal (the entry's icon tile rotates in), reinforcing that a Burn Track entry *is* a played card becoming visible.

## Spacing Scale

Declared values (must be multiples of 4) — identical to the Phase 1–3 scale in `01-UI-SPEC.md`, used
via Tailwind's default numeric utilities (`gap-N`, `px-N`, `py-N`); no new `--spacing-*` theme keys.

| Token | Value | Usage in this phase |
|-------|-------|-------|
| xs | 4px | Gap between a Burn Track entry's icon and its round-number label; gap between a round-history row's round number and its headline text |
| sm | 8px | Gap between round-history rows; gap between Burn Track entries in the track list; gap between the two Intel drawer tabs |
| md | 16px | Default padding inside the Intel drawer (matches `MatchChat`'s existing `p-6`... see exception below); default padding inside an expanded `StepThrough` drill-down row |
| lg | 24px | Padding around the Intel drawer's tab content area |
| xl | 32px | Not used this phase |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions:
- **`MatchIntelDrawer` reuses `MatchChat`'s exact `p-6` (24px) panel padding**, not the `md` (16px) token — this is a direct visual match to the sibling corner-dock panel already shipped in Phase 3, not a new spacing decision; components should copy `MatchChat.tsx`'s container classes verbatim for the drawer chrome.
- **44px minimum click/tap hit-target**, carried over from 01-UI-SPEC.md, applies to the Intel drawer's collapsed toggle, its tab buttons, and every round-history row's expand control.

## Color

Reuses the exact `app/globals.css` `@theme` tokens from Phases 1–3. Zero new UI-chrome colors.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (`--color-surface`) | Page background, Intel drawer background |
| Secondary (30%) | `#f1f5f9` (`--color-surface-secondary`) | Round-history row background, Burn Track entry tile background, Intel drawer inactive-tab background |
| Accent (10%) | `#2563eb` (`--color-accent`) | See reserved-for list below |
| Destructive | `#dc2626` (`--color-destructive`) | See reserved-for list below |
| Border | `#e2e8f0` (`--color-border`) | All new row/tile/drawer/tab borders |
| Muted text | `#64748b` | Round-history "no major events" fallback text, Burn Track empty-state body text |

**Accent reserved for, and only for:**
- The Intel drawer's active tab (border+text, matching the existing selected-preset-button pattern from `02-UI-SPEC.md`)
- The Intel drawer's collapsed-toggle unread/new-Burn-Track-entry count badge fill (matching `MatchChat`'s existing unread-badge pattern exactly)
- Focus rings on any new focusable control (drawer toggle, tab buttons, row-expand buttons), reusing the existing `focus:border-[#2563eb]` pattern
- Primary-variant `Button` hover fill (`#1d4ed8`, blue-700 — one step darker than the existing `#2563eb` accent), applied via the shared motion/interaction utility to every existing primary CTA (Create Game, Join Game, Ready Up, Submit Orders, Save Loadout, Next) as part of this phase's hover-state pass — no new buttons, only a hover treatment added to buttons that already exist

**Destructive reserved for, and only for:**
- A round-history row's left border stripe when that round's headline event is an `AGENT_BURNED` affecting the viewer's own agent (mirrors `Banner.tsx`'s and `02-UI-SPEC.md`'s existing "destructive as accent-stripe, never full-panel fill" pattern) — background stays neutral secondary, text stays `#0f172a`
- Destructive-variant `Button` hover fill (`#b91c1c`, red-700 — one step darker than `#dc2626`), same hover-pass treatment as the primary variant above, applied to the existing "Kick" and "Retract order" buttons

Everything else — Burn Track entry chrome, Intel drawer chrome, round-history row chrome — uses
white/slate neutrals. **Sector palette reuse:** a non-redacted Burn Track entry's sector swatch reuses
`02-UI-SPEC.md`'s exact fixed four-color palette (`RED #dc2626` / `BLUE #2563eb` / `GOLD #ca8a04` /
`GREEN #16a34a`) paired with its 3-4 letter uppercase text label — same "color is never the only
signal" rule (`apps/web/components/CLAUDE.md`) already governing `CardGrid.tsx`. A **redacted** entry
(`sector === null`, Cutout) renders with **no swatch and no sector text at all** — not a neutral
placeholder swatch, not a "Redacted" label — per D-05: the entry shows only its icon label and round
number, exactly the incomplete picture an opponent would see. Do not add a "Cutout"/"Redacted" tag;
the deduction is meant to come from the player noticing the *absence* of color, matching
`docs/GAME_DESIGN.md` §6.1's Cutout description precisely.

## Motion Contract

New this phase — POLISH-01's central deliverable. `apps/web/lib/motion.ts` (D-08) is the single source
for every duration/easing/reduced-motion decision below; no component may hardcode its own duration or
re-derive `useReducedMotion()` logic once this module exists (`StepThrough.tsx` is refactored onto it
in the same phase, not left as a second pattern).

| Token | Value | Usage |
|-------|-------|-------|
| `DURATION.fast` | 0.15s | Hover fill changes, button pending-state opacity change |
| `DURATION.base` | 0.25s | Row/list-item entry (matches `StepThrough.tsx`'s existing `duration: 0.25`), panel expand/collapse |
| `DURATION.slow` | 0.35s | Card flip (deckbuilder tile selection, Burn Track entry call-out) |
| `EASING.standard` | `[0.4, 0, 0.2, 1]` (Tailwind's "ease-out" curve) | All transform/opacity animations in this module — the first explicit easing token in the codebase; `StepThrough.tsx`'s current usage has none and adopts this on refactor |

**Reduced-motion policy** (`prefers-reduced-motion`, read via `useReducedMotion()` from `motion/react`,
exactly as `StepThrough.tsx` already does):
- Every **transform-based** animation (translate/scale/rotate — row slide-in, card flip, panel
  expand/collapse motion) is suppressed under reduced motion: content still appears/disappears, but
  via `initial={false}` (an instant cut, matching `StepThrough.tsx`'s existing documented behavior),
  never a zero-duration tween that still flashes.
- Simple **CSS color/opacity transitions** on hover and focus (button hover fill, focus ring) are
  **not** suppressed under reduced motion — they carry no vestibular risk and remain interactive
  affordances; these are implemented as plain Tailwind `transition-colors duration-150` classes, not
  through the `motion` package, so they need no `useReducedMotion()` check at all.
- The **card flip** treatments (deckbuilder tile selection, Burn Track entry call-out) are the one
  case that must degrade gracefully rather than vanish: under reduced motion they resolve to an
  instant state swap (selected/unselected fill, or the new entry simply present) with no rotation —
  never withheld, only its transition removed, mirroring `StepThrough.tsx`'s row-reveal precedent.
- Loading/pending feedback (`Button`'s existing `pending` prop) stays exactly as-is — reduced opacity,
  no spinner, unaffected by motion preference since it was never motion-based (`01-UI-SPEC.md` D-10).

**New motion applications this phase** (all routed through `apps/web/lib/motion.ts`):
1. Round-history row entry (list mount) — `fadeSlideUp` variant, `DURATION.base`
2. Round-history row expand/collapse into `StepThrough` — height/opacity transition, `DURATION.base`
3. Burn Track entry call-out on append (D-06) — `cardFlip` variant, `DURATION.slow`
4. Deckbuilder `CardGrid` tile select/deselect — `cardFlip` variant, `DURATION.slow`
5. Intel drawer and `MatchChat` expand/collapse — `fadeSlideUp` variant (from the corner), `DURATION.base` (both panels move onto the shared utility; `MatchChat` currently has zero motion — 03-UI-SPEC.md explicitly deferred this to Phase 4)
6. All primary/destructive `Button` hover states — CSS-only `transition-colors duration-150`, not the `motion` package (see reduced-motion policy above)
7. Page-mount entry on Home, `/deck`, `/lobby/[code]`, `/match/[code]` — a single top-level `fadeSlideUp` on the page's root container, `DURATION.base`, so navigating between routes doesn't feel like a hard cut — this satisfies "page transitions" from POLISH-01 without introducing route-transition machinery Next.js App Router doesn't natively provide
