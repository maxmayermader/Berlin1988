## Phase Goal

**As a** group of players, **I want to** go from the home page through a lobby into a complete 14-round match and see a result, **so that** we can actually play Berlin 1988 in a browser.

This plan delivers the fifth vertical slice: *watch the clock, watch the others lock in, then read what happened one step at a time*.

<objective>
Build the two surfaces that make a simultaneous-turn round legible: the order-phase HUD — "N of M submitted", a countdown to the server's deadline, and a fixed four-slot locked-in row — and the click-to-advance resolution report that replays `PlayerView.lastRound` in the engine's fixed eleven-step order.

Purpose: `docs/ARCHITECTURE.md` §9 and `apps/web/CLAUDE.md` both call the resolution replay the screen that matters most, because simultaneous turns are the game's central mechanic and its steepest onboarding cliff — players learn the priority rules by watching this, not by reading them. The failure modes are specific and both are cheap to prevent now: a locally-incremented counter that drifts or lies, and a step-through that puts the whole round in the DOM and reveals it with CSS.

Output: a round that reads as a story. Submit, watch the count fill and the clock run down, then step through what everyone did, then go again.
</objective>

**`apps/web/lib/clock.ts` — the countdown as pure arithmetic.** Export `secondsRemaining(deadlineAt: number | null, now: number): number` returning `Math.max(0, Math.ceil((deadlineAt - now) / 1000))` and 0 for a null deadline, `clockLabel(seconds)` returning `m:ss`, `URGENT_THRESHOLD_SECONDS = 10`, and `isUrgent(seconds)`. The clamp at zero is the whole point: the deadline is a server timestamp and a client whose clock runs fast will compute a negative remainder in the window between the deadline passing and the resolution frame arriving. It must show 0 and hold there.

**`apps/web/lib/stepThrough.ts` — the pacing as a pure reducer.** Export `REVEALED_AT_START = 1`, `initialReveal(log)`, `advance(state, log)`, `revealedEvents(log, state)` returning `log.slice(0, state.revealed)`, and `isComplete(log, state)`. Revealing is slicing. The unrevealed tail is not returned, so it never reaches a component, so it cannot end up in the document under any styling — that is the mechanism by which MATCH-05's "never reveals information ahead of its rules-defined step" is enforced rather than merely intended. The first event is revealed immediately because it is always `ROUND_START`, which announces nothing.

**`apps/web/components/hud/SubmittedCount.tsx`** takes `{ committed, total }` and renders `"{N} of {M} submitted"` in the Label role. Both numbers come from the store, which is written only by `OPPONENT_COMMITTED` and `VIEW` frames. The local player's own submission raises N when the server says so, not when the button is pressed. One component serves every seat count from 1-of-1 to 4-of-4; there is no branch for a solo match or an AI-filled one, because a bot seat routes through the identical submit path and is counted identically.

**`apps/web/components/hud/RoundClock.tsx`** takes `deadlineAt` and renders `clockLabel(secondsRemaining(deadlineAt, Date.now()))`, recomputing on an interval or animation frame. The interval controls only *when the component re-reads the wall clock*; the value itself is always recomputed from the server's absolute timestamp, so a suspended tab resumes at the correct number rather than resuming a stale count.

**`apps/web/components/hud/LockedInRow.tsx`** takes the seat list and the `committed` map and renders four slots, always four, matching the `MatchSettings` seat maximum. Occupied slots show a truncated codename plus a locked-in badge when that seat's committed count equals its live agent count; unoccupied slots render as empty placeholders of the same size. The fixed layout is what stops the row reflowing as players submit in arbitrary order. A badge says only that the seat is locked in — it has no prop that could carry an action, and the frame that feeds it has no such field.

**`apps/web/components/resolution/StepThrough.tsx`** takes `{ log, round, isFinal }` and renders `revealedEvents(log, state)` as rows, with a "Next" button while `!isComplete`. Once complete, "Next" is replaced by "Continue to Round {round + 1}" which clears the reveal state and returns the route to composing — except when `view.outcome` is non-null, where nothing is offered and the result screen follows automatically (Plan 01-06). Copy comes verbatim from the Copywriting Contract.

**`apps/web/components/resolution/ResolutionEventRow.tsx`** renders one event through `format.eventText(event)`. Add `eventText` to `apps/web/lib/format.ts` with a case per `ResolutionEvent` member and no default branch, so `noFallthroughCasesInSwitch` and exhaustiveness checking make a new event type a compile error rather than a blank row. Events whose agent id is nulled by fog render as prose about an unnamed agent — "an agent was burned at Kreuzberg" — never as an empty slot. The same string feeds the visible row and its accessible announcement, so the two cannot drift.

**`apps/web/app/match/[code]/page.tsx`.** Add the two sub-states around Plan 01-04's composer: while `view.phase === 'ORDERS'` render the board, the composer and the HUD; when a `ROUND_RESOLVED` frame arrives, render the board and the step-through instead, keyed on `view.round` so a new round resets the reveal state.
